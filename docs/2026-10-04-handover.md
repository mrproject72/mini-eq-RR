## Gotchas learned this session

- **`gio` vtable closures are `Send`**, which is why `MiniEqAppHandler` requires
  `Send + Sync` and why the handlers cannot touch GTK directly. The command
  queue exists for exactly this reason — do not "simplify" it away.
- **`Variant::get` returns `Option`, not `Result`** (glib 0.22).
- **`params` is the whole argument tuple.** `get::<bool>()` never matches;
  use `get::<(bool,)>()`.
- **`array_from_iter::<Variant>` infers the wrong element type** and aborts the
  process from a GLib tick (panics cannot unwind there). Always pass the
  element type to `array_from_iter_with_type`.
- **A `RefCell` callback must not re-borrow its own owner.** The preset panel's
  apply callback runs inside `presets.borrow_mut()`; reading the panel from
  there panics. Sync after the borrow is released.
- **`set_active()` does not emit `state-set`** but does emit `notify::active`.
  Choose based on whether programmatic changes should re-enter the handler.
- **`bus_own_name_on_connection`'s owner id must be retained** — dropping it
  releases the well-known name.

## Do not re-attempt

- **Value-gating `AnalyzerLevelsChanged`.** Silence gives an identical spectrum
  every frame, so a change detector never fires. It is time-throttled at 100 ms
  for this reason.
- **Re-entering `presets` from its own apply callback.** Panics.
## Update — monitor follow the EQ output (2026-10-04, later)

Fixed the user's "monitor stops when I switch output" report. Root cause and
details in `docs/BUGS.md`; summary in `docs/2026-10-04-updates.md`. The invariant
now enforced in `window.rs` is **the output monitor always taps the sink the
filter chain targets** (`resolve_monitor_target`), and `engine_sink` is shared
mutable state (`Rc<RefCell<String>>`) rather than a value captured once at
startup. If you add another place that starts the monitor, use
`resolve_monitor_target()` — three call sites had drifted to
`default_output_sink()` and had the same latent bug.
