# 2026-10-06 updates — EQ regressions + live-test automation

## User-reported regressions (all fixed, all covered by tests)

1. **Header switch naming.** The Off/On switch no longer carries the
   "System-wide EQ" name; tooltip is now `Enable/Disable EQ`.
   `Selected`/`Reroute` moved from the header into the sidebar's **Output
   Controls** panel ("EQ scope" row). (`window.rs`, `window_utility.rs`)
2. **Switch Off never unrouted.** The OFF handler only flipped UI state and
   left streams pointed at `mini_eq_sink`. It now calls
   `unroute_all(fallback=engine_sink)`; switch-on re-targets the chain onto
   the chosen device and follows with the monitor before routing.
3. **Engine never started ("Default Device", dead monitor).** The `default`
   metadata bind is lazy, so `default_output_sink()` was `None` at startup.
   `PipeWireBackend::new` now primes it (`prime_default_sink`), and `main.rs`
   waits up to 3 s for the property (it arrives just after the bind
   roundtrip), falling back to the first listed sink.
4. **Curve dropdown showed only the current preset.** Model was customs-only
   with no `(none)` entry. Now `(none)` + built-ins + customs via pure
   `window_presets::curve_model_names()` (+ unit test). Both dropdown
   refreshes only rebuild on real change with re-entrancy guards (the 330 ms
   rebuild was re-firing the link handler and resetting selections).
5. **Device hops lost monitor/EQ.** Two backend fixes from live-test evidence:
   - `auto_route_to_sink(VIRTUAL)` clobbered `current_sink`, so the monitor
     resolved to `mini_eq_sink` itself. New `chain_output_sink` field stays
     physical; `resolve_monitor_target` uses it.
   - `unroute_all`/`suspend_routing` enumerated scope-filtered streams, so
     after a device switch (physical `current_sink`) EQ-pointed streams were
     out of scope under Selected and never restored; a re-route then recorded
     the EQ target as "own", cementing it past quit (the "stream stops"
     bug, reproduced live). New `restorable_output_streams()` includes
     recorded + EQ-pointed streams; auto-route no longer records the virtual
     sink as origin; auto-route scopes against the physical chain output too
     (re-on after off-to-fallback routed 0 streams before this).
6. **Remote toggles ran twice.** `set_active()` emits `state-set` in GTK4
   (four code comments claimed otherwise). The D-Bus drain now blocks the
   handler around programmatic sets via shared `SignalHandlerId` cells.

## New D-Bus API (driven by the live test, useful for the Shell extension)

`SetOutputSink(s)` (`""` = follow default), `SetMonitorEnabled(b)`,
`SetMonitorSink(s)` (`""` = follow EQ output). New `RemoteCommand` variants
flow through the existing queue + `apply_remote_command` (same code paths as
the dropdowns). Capabilities extended.

## Follow-up (same day): Selected device-switch dragged audio along

Report: with EQ on (Selected) and audio on the default device, changing the
Output dropdown moved the playing audio to the new device. Expected: it stays
put. Reproduced in `tests-live` and fixed:

- New `RoutingEngine::rescope_routing()` (returns pruned/adopted): after a
  chain move, or when narrowing to Selected, hands back recorded streams whose
  *effective* device (recorded target, else the system default for
  target-less streams) is not the new device; adopts unrecorded streams
  explicitly aimed at it (plus target-less ones when the new device is the
  default, so switching away and back re-takes them). No-op under Reroute /
  when not routed / when unresolvable.
- Wired into `retarget_output` (live-move and rebuild paths; rebuild keeps
  full re-route under Reroute), the Output dropdown, D-Bus `SetOutputSink`,
  the default-sink watcher, and both mode-switch paths (Reroute still
  auto-routes, Selected now rescope-prunes).
- `auto_route_to_sink_with_mode` additionally scopes against the physical
  chain output (re-on after off-to-fallback routed 0 streams before this),
  and `processing_path_targets` treats the chosen chain output as ours, not
  foreign.
- Live test: new `tone left the EQ on device switch`, `tone not moved to the
  new device`, `tone re-adopted after switch back` checks — **27/27 pass**.

User decision: while streams are routed in Selected mode, the chain stays
where the music plays ("Keep EQ where music plays").

- Manual Output switches away are now REFUSED while routed streams depend on
  the chain (Selected only; Reroute streams follow, EQ-off switches freely):
  dropdown reverts + toast explains; D-Bus `SetOutputSink` returns unchanged

  passthrough, seed into `output/` (real preset storage; `presets/` is stale
  legacy). **33/33 live pass**, 132 unit pass.

## Multi-chain EQ (2026-10-06, Phases 1-3 done)

Architecture moved to per-device EQ, per the user's confirmed spec: each
output device owns an independent EQ context (on/off, curve/preset, streams);
the selected device is the edit context; switching devices changes no audio.

- **Naming** (`core.rs`): `eq_virtual_sink_for(dev)` /
  `eq_filter_output_for(dev)`; unit-tested. Legacy `mini_eq_sink` prefix
  preserved so prefix matching kept working.
- **Backend** (`pipewire_backend.rs`): `device_chains` map keyed by physical
  sink; `ensure_device_chain` loads the module per device and registers the
  sink with routing; `drop_device_chain` unloads + unregisters;
  `set_device_bands` / `set_device_preamp` / `device_push_live` /
  `device_physical_sinks` / `device_bands` / `has_device_chain` /
  `has_device_live_node` helpers. Tick push is per-device with a pending-retry
  set (live-proxy arrival grace).
- **Routing** (`routing.rs`): `eq_sinks` registry (eq->physical);
  scope targets derivation for device sinks; `rescope_device`;
  `unroute_device` (per-device OFF); `has_routed_streams_for`;
  `processing_path_targets`/`still_on_eq`/restorable paths cover every
  registered chain. `unroute_device` stops devices' streams from being
  moved/pruned.
- **Window**: header switch mirrors the SELECTED device's own on/off (OFF
  unroutes only that device, ON ensures its chain with its linked-preset
  curve + routes into it); dropdown/D-Bus select = edit-context switch (no
  chain rebuild, no stream moves, no toast/refuse); Reroute mode routes all
  streams through the selected device's chain; narrowing back to Selected
  re-scopes every chain; D-Bus SetRouting/SetMonitorEnabled just set the
  widget (its handler does the work — set_active emits state-set in GTK4);
  default-sink changes are logged but no longer re-target any chain; A/B
  bypass applies to every known chain.
- **Startup**: device chain created for default sink with its own linked
  preset; auto-route points into that device's eq sink, not the global
  singleton.
- **Live test** (33 checks): tone on eq(A); switching select A→B keeps A's
  stream on eq(A), shows B's own preset, `routed` flips to B's state; B's EQ
  ON creates its chain and leaves A alone; B EQ never carries A's stream.
  All 33 pass (0.8 s). Unit: 133 pass. clippy/fmt clean.
