# 2026-10-07 — flatpak-vs-native audibility investigation (no code change)

Reported symptom (flatpak): sliders do nothing, A/B inaudible.

Findings, all verified live:

- **No flatpak-vs-native difference exists.** Same commit (`07448ca`), same
  routing results: metadata lands as proper integer `target.object`, links go
  active into the per-device EQ sink, in both builds.
- **DSP proven working both directions** via the app's own analyzer on a
  3770 Hz tone with a +15 dB test preset: wet 0.58 vs bypass 0.41 (bypass
  equals direct passthrough). Push path, coefficients and bypass all correct.
- **What actually broke the user's sessions:**
  1. Two app instances fighting over one D-Bus name (manual flatpak +
     automated native probes) — calls and reads landed on the wrong process.
     Always `ps`-check for a single instance before trusting any observation.
  2. WirePlumber per-app route restore pinning streams to explicit devices
     (incl. dead EQ serials from earlier runs), so Selected scope legitimately
     skipped them while the UI said on. Covered since `4c9a41f` by the
     effective-default rule + zero-match toast.
  3. The A/B "no difference" moment had `routed=false` — bypass compared two
     identical unrouted signals.
  4. Two same-named Waterfox streams, one EQ'd and one direct, diluting
     perception; plus tone-lifetime races invalidating several early
     wet/dry measurements (always use a long tone + verify liveness).
- Test-hygiene rules this produced: single instance, one audio source,
  `pw-play --target` pinning, hermetic bus, verify stream liveness at every
  measurement. Several are already encoded in `tests-live/`.
