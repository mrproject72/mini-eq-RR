# 2026-10-08 — truthful `routed`, link fallback for sandboxes, idle-CPU audit

## 1. GetState `eq_flowing` / `flowing_streams` (read-back truth, not intent)

Symptom (flatpak): EQ on, `GetState` says `routed=true`, sliders do nothing,
A/B inaudible. Root cause, proven live: every route/adopt path actuates via
`default`-metadata `target.object` writes, and the sandbox daemon silently
discards them (`pw-metadata` from inside the sandbox reports OK, read-back
unchanged). The app then reported intent as fact.

- New `RoutingEngine::flowing_count()` counts streams verifiably inside our EQ
  sinks (metadata target OR live links). Published throttled (~500 ms) as
  GetState `eq_flowing` + `flowing_streams`. `routed` keeps its machinery-on
  meaning; the D-Bus contract documents the split.
- Live test: `eq_flowing=true` + `flowing_streams>=1` with tone routed,
  per-device persistence across a single-device off, `false` once all chains
  are off.

## 2. Real link fallback when metadata does not take

Probed from inside the sandbox: `pw-link` create AND destroy of foreign-stream
links both succeed. So where metadata is discarded the engine now wires real
port links stream→EQ and severs the competing direct links (link first, sever
second: never pathless, never doubled). Rules that keep it safe:

- Actuation is verify-gated: metadata match or existing EQ links means hands
  off (native behavior byte-identical: zero links created).
- The write's property echo was observed arriving AFTER the write's roundtrip,
  so verification is deferred (~1.5 s grace, re-checked on the pump tick),
  never acted on first mismatch. Acting early once severed the session
  manager's in-flight path and silenced the stream (caught by T3b).
- Heal rule: our links drop only once an independent path is observably live
  (EQ-serial metadata AND non-ours links); never on metadata alone. Orphan
  links (unowned streams) are destroyed, not kept. Teardown on hand-back,
  per-device unroute, global unroute, and rebuild.
- `create_link` previously had zero callers; `stream_link_targets` only read.
  Both now actuate with full teardown.

## 3. Late-stream race (T6c) fixed at the root

A send-then-pin stream (`pw-play --target=B`: node property first, metadata
follows) was armed for the default device before its real target arrived,
recorded, then skipped forever. Selected scope now adopts empty-target
streams only on link evidence; link arrivals re-flag dirty (registry listener
now also fires on Link globals). 47/47 live checks green.

## 4. Idle-CPU audit (~7% of one core at idle)

Measured per-thread: 100% of the burn is the main GTK thread; DSP 0%,
headless 0.0%. Fixed three unjustified items (paint-on-demand graph layers,
mtime-cached links config, change-gated loudness labels). Remaining ~0.4% is
legitimate live cost: 30 fps spectrum of a real (USB noise-floor) signal +
contracted 10/s D-Bus emissions + timers. Analyzer on/off identical; the
spectrum at "silence" never bit-settles, so that redraw is earned.
