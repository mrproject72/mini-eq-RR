# 2026-10-08 — truthful `routed`, link fallback for sandboxes, idle-CPU audit

## 1. GetState `eq_flowing` / `flowing_streams` (read-back truth, not intent)

Symptom (flatpak): EQ on, `GetState` says `routed=true`, sliders do nothing,
A/B inaudible. Root cause, proven live: every route/adopt path actuates via
`default`-metadata `target.object` writes, and the sandbox daemon silently
discards them (`pw-metadata` from inside the sandbox reports OK, read-back
unchanged). The app then reported intent as fact.

- New `RoutingEngine::flowing_count()` counts streams verifiably inside our EQ
  sinks (metadata target OR live links). Published throttled (~500 ms) as
  GetState `eq_flowing` + `flowing_streams`. `routed` keeps its machinery-on
  meaning; the D-Bus contract documents the split.
- Live test: `eq_flowing=true` + `flowing_streams>=1` with tone routed,
  per-device persistence across a single-device off, `false` once all chains
  are off.

## 2. Real link fallback when metadata does not take

Probed from inside the sandbox: `pw-link` create AND destroy of foreign-stream
links both succeed. So where metadata is discarded the engine now wires real
port links stream→EQ and severs the competing direct links (link first, sever
second: never pathless, never doubled). Rules that keep it safe:

- Actuation is verify-gated: metadata match or existing EQ links means hands
  off (native behavior byte-identical: zero links created).
- The write's property echo was observed arriving AFTER the write's roundtrip,
  so verification is deferred (~1.5 s grace, re-checked on the pump tick),
  never acted on first mismatch. Acting early once severed the session
  manager's in-flight path and silenced the stream (caught by T3b).
- Heal rule: our links drop only once an independent path is observably live
  (EQ-serial metadata AND non-ours links); never on metadata alone. Orphan
  links (unowned streams) are destroyed, not kept. Teardown on hand-back,
  per-device unroute, global unroute, and rebuild.
- `create_link` previously had zero callers; `stream_link_targets` only read.
  Both now actuate with full teardown.

## 3. Late-stream race (T6c) fixed at the root

A send-then-pin stream (`pw-play --target=B`: node property first, metadata
follows) was armed for the default device before its real target arrived,
recorded, then skipped forever. Selected scope now adopts empty-target
streams only on link evidence; link arrivals re-flag dirty (registry listener
now also fires on Link globals). 47/47 live checks green.

## 4. Idle-CPU audit (~7% of one core at idle)

Measured per-thread: 100% of the burn is the main GTK thread; DSP 0%,

# Session addendum (evening): stream-killing in the sandbox root-caused and fixed

## 6. In-process link-factory fallback never lands server-side (user report)

Symptom (flatpak, installed `33dc6ad` build): "switch the EQ on and it kills
the current stream on the device and leaves it playing somewhere else".
Reproduced with `RUST_LOG` debug on the live sandbox:

```
WARN  Stream 67: metadata write did not take (sandboxed daemon?)
INFO  Created link 6 (67:133 -> 42:76)      # link-factory records ids locally
WARN  Stream 67: severing direct link 119 -> device
INFO  Destroyed link 119                    # real links destroyed
```

The "Created" links never instantiate server-side (pw-dump showed zero links
on the stream) — the app recorded phantom ids, destroyed the stream's real
device links, and the stream went pathless → WirePlumber re-homed it.
`ef10b31` (pw-link binary + server-side verify before sever) is the fix;
verified end-to-end in the sandbox after installing the CI bundle:
route ON → stream linked into the EQ sink, `eq_flowing=true`,
`flowing_streams=1`, player alive.

## 7. Unroute went pathless in the sandbox (fixed `e4b05c4`)

Sandbox log: `UnrouteDevice(...): 0 restored, 0 to fallback` — the unroute
identifies "our" streams by metadata `target.object` (discarded by the
sandbox daemon), matched nothing, then dropped the fallback link anyway →
stream pathless → player died on stream error. `unroute_device` now also
recognizes streams held by fallback links into this EQ and restores each
with real port links into its recorded original device — verify-before-drop,
link-first so the stream is never pathless; a failed restore keeps the link
and the heal retries. Pairing/pw-link plumbing shared via
`pair_stream_ports` + `port_id_refs`.

## 8. Diagnostics traps (cost half a day, documented so they are not repeated)

- **gdbus bool syntax**: `SetRoutingEnabled b:true` is a PARSE ERROR
  (`expected value: b:true ^`) — gdbus wants bare `true`/`false`. Every
  D-Bus probe using `b:` silently never reached the app; one suspected
  "remote toggle is a no-op" bug (Bug A) was invalidated by this. The
  harness's `dbus.py` wrapper is correct; only raw gdbus calls trip.
- **Backgrounded processes die with the tool call**: anything started with
  `&` (flatpak, pw-play) must be started under `setsid nohup ... & disown`
  or it is killed when the tool call times out. Three test rounds were
  invalidated by flatpak/tone deaths this caused.
- **Test tones expire**: 90 s/600 s tones finished mid-experiment and faked
  "stream killed" symptoms; the `ps -p $PID` check also hits the setsid
  wrapper, not the player child — check the stream node in pw-dump instead.
- **Wet/dry 0.0/0.0 RMS in T3b was environmental**: a leftover flatpak
  instance polluted the captures; with a clean environment the suite is
  47/47 (`wet=27119.2 dry=8439.8`, ~+10 dB measured).
- **Leftover instances hold the flock**: a second launch (native or
  flatpak) is refused while one runs; kill by PID before testing.

## 11. Two-device separate-EQ test (the priority test, fixed `53c0263`)

Two streams on two different device outputs (1000 Hz → pci analog,
300 Hz → Logitech H570e), each device's chain with its own curve
(+12 dB @ 1 kHz vs +12 dB @ 300 Hz), equalized separately. The test exposed
two more bugs, both fixed:

- **Metadata-less streams were swept into the default device's EQ.**
  `pw-play --target=X` sets the target in node properties, not metadata;
  such a stream reads as `target=None` and `scope_allows` treated it as
  default-aimed — the Logitech-aimed tone landed in the PCI chain and both
  streams were equalized together (debug trace: the same `target=None`
  streams flipped from `skip (out of scope)` to `ROUTABLE` between scope
  passes). `is_in_scope` now checks live link evidence for metadata-less
  streams under Selected: a link into a sink that is neither this scope, the
  default, nor our own machinery puts the stream out of scope. Reroute still
  takes everything.
- **A chain created at startup ran the neutral curve forever.** The
  route-on path loaded the device's linked preset only inside the
  chain-creation branch; a chain created at startup (persisted
  `eq_enabled=true`) never got its preset. The linked curve now applies on
  every route-on.

**Result 9/9**: both streams in their own chains; curves applied per output
(`A: wet=27129.6 dry=8655.1`, `B: wet=27072.3 dry=8424.2` — 3.1x/3.2x);
**independence verified** (`B: 27071.5 → 27074.6` when A's route went off);
A's streams handed back on unroute. Semantics note: the **A/B bypass switch
is global** (upstream-consistent) and the **route switch is per-device** —
the independence test uses the route switch; an attempt to make the eq push
per-device was reverted because it made the A/B switch inert. Live suite
46/47 (one pre-existing WP-race flake); 134 unit tests; clippy/fmt clean.

## 12. Mono collapse: pw-link multi-pair (user report, fixed `3971cfa`)

Symptom (flatpak): "when I move the sliders, the output goes to only one
channel mono, no EQ changes; another stream: same result". Root cause,
settled empirically on a live stream: **`pw-link` connects exactly ONE
output/input pair per invocation** — `pw-link 113 57 126 123` exits 0 and
creates only the first pair. The fallback packed all pairs into one call,
so a stereo stream's FR channel never linked: Waterfox had 2 output ports
and 1 active link into the EQ sink (mono audio). Fixed: one `pw-link -w`
invocation per pair; partial channels destroy what landed (the stream
stays on its device, stereo there) and the verify counts live links
against the pair count instead of any-match. Same fix in the unroute
restore path. **Verified live on a real app stream**: ringrtc with 2 output
ports → 2/2 active links into the EQ, stereo preserved.

Diagnostics traps that again cost time:

- **A running instance pins the old build**: `flatpak install --bundle`
  replaces the files, but the running instance keeps its mapped old binary.
  A 3-hour-old instance made two verification rounds test the wrong build.
  Kill by PID (D-Bus Quit hung once) before installing and verifying.
- **`flatpak run --command=sh` starts a second sandbox** — fine for
  inspection (the flock is per-app-binary), and it is how the environment
  and mounted config were verified.
- **The host cannot see the sandbox's bind mounts**: the
  `xdg-config/mini-eq` mount is only visible inside the sandbox
  (`$XDG_CONFIG_HOME/mini-eq` there); host-side stat/inode checks
  mislead. Inside the sandbox the mount mirrors the host config correctly —
  presets ARE shared (the earlier "needs a follow-up" concern was wrong).
- **SetPreset only finds presets present at app startup** (the panel's
  library scan): a preset file created after launch fails with
  `os error 2`. Seed presets before launching the app under test.
- **flowing_streams over-counted** when a stream was adopted by metadata
  write alone in the sandbox (the write is discarded, the stream is on its
  device) — treat `eq_flowing`/`flowing_streams` as a hint and always
  confirm the links in pw-dump.

## 13. Gold path: two-device curve preservation (2026-10-10, `24f39bd`)

`tests-live/twodev_gold_path.sh` is the durable form of the user's test:
two streams on two outputs (stereo tones, both 1 kHz), Selected mode,
select device 1 + apply curve 1 (+12 dB), device 2 + curve 2 (−12 dB),
switch back and verify curve 1 is preserved on BOTH (a 24 dB measured gap,
not a guess), then quit and verify the streams are not broken. Booleans via
`dbus.py` need the `b:` prefix (bare args parse as strings and the call is
a silent no-op — cost one run); `--flatpak` drives the installed bundle;
`GOLD_KEEP=1` keeps the app log for post-mortem.

Two bugs the gold path exposed, both fixed:

- **dbus.py booleans**: bare `true` through the wrapper is a string and the
  call never reaches the app. `b:true` is the correct form (raw gdbus wants
  bare `true` — opposite conventions, documented in both places).
- **Exit restore went pathless in the sandbox** (`affb72a`): `unroute_all`
  (the exit path, unlike `unroute_device`) restored recorded streams via
  metadata writes only — discarded by the sandbox daemon — then dropped
  every fallback link (gold path step 6a: NO-LINKS 4 s after quit). The
  exit restore now also restores fallback-held streams with real port
  links into their recorded original device, link-before-drop, and destroys
  the EQ links only once the device links are verified live.

**Result: 7/7 native and 7/7 `--flatpak`** — curves applied per output
(device 1: 24425.1 wet, device 2: 1587.1; preservation identical on
switch-back), streams handed back on quit, players alive, app exited.
Live suite 47/47; 134 unit tests; clippy/fmt clean.
