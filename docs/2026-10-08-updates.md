# 2026-10-08 — truthful `routed`, link fallback for sandboxes, idle-CPU audit

## 1. GetState `eq_flowing` / `flowing_streams` (read-back truth, not intent)

Symptom (flatpak): EQ on, `GetState` says `routed=true`, sliders do nothing,
A/B inaudible. Root cause, proven live: every route/adopt path actuates via
`default`-metadata `target.object` writes, and the sandbox daemon silently
discards them (`pw-metadata` from inside the sandbox reports OK, read-back
unchanged). The app then reported intent as fact.

- New `RoutingEngine::flowing_count()` counts streams verifiably inside our EQ
  sinks (metadata target OR live links). Published throttled (~500 ms) as
  GetState `eq_flowing` + `flowing_streams`. `routed` keeps its machinery-on
  meaning; the D-Bus contract documents the split.
- Live test: `eq_flowing=true` + `flowing_streams>=1` with tone routed,
  per-device persistence across a single-device off, `false` once all chains
  are off.

## 2. Real link fallback when metadata does not take

Probed from inside the sandbox: `pw-link` create AND destroy of foreign-stream
links both succeed. So where metadata is discarded the engine now wires real
port links stream→EQ and severs the competing direct links (link first, sever
second: never pathless, never doubled). Rules that keep it safe:

- Actuation is verify-gated: metadata match or existing EQ links means hands
  off (native behavior byte-identical: zero links created).
- The write's property echo was observed arriving AFTER the write's roundtrip,
  so verification is deferred (~1.5 s grace, re-checked on the pump tick),
  never acted on first mismatch. Acting early once severed the session
  manager's in-flight path and silenced the stream (caught by T3b).
- Heal rule: our links drop only once an independent path is observably live
  (EQ-serial metadata AND non-ours links); never on metadata alone. Orphan
  links (unowned streams) are destroyed, not kept. Teardown on hand-back,
  per-device unroute, global unroute, and rebuild.
- `create_link` previously had zero callers; `stream_link_targets` only read.
  Both now actuate with full teardown.

## 3. Late-stream race (T6c) fixed at the root

A send-then-pin stream (`pw-play --target=B`: node property first, metadata
follows) was armed for the default device before its real target arrived,
recorded, then skipped forever. Selected scope now adopts empty-target
streams only on link evidence; link arrivals re-flag dirty (registry listener
now also fires on Link globals). 47/47 live checks green.

# Session addendum (evening): stream-killing in the sandbox root-caused and fixed

## 6. In-process link-factory fallback never lands server-side (user report)

Symptom (flatpak, installed `33dc6ad` build): "switch the EQ on and it kills
the current stream on the device and leaves it playing somewhere else".
Reproduced with `RUST_LOG` debug on the live sandbox:

```
WARN  Stream 67: metadata write did not take (sandboxed daemon?)
INFO  Created link 6 (67:133 -> 42:76)      # link-factory records ids locally
WARN  Stream 67: severing direct link 119 -> device
INFO  Destroyed link 119                    # real links destroyed
```

The "Created" links never instantiate server-side (pw-dump showed zero links
on the stream) — the app recorded phantom ids, destroyed the stream's real
device links, and the stream went pathless → WirePlumber re-homed it.
`ef10b31` (pw-link binary + server-side verify before sever) is the fix;
verified end-to-end in the sandbox after installing the CI bundle:
route ON → stream linked into the EQ sink, `eq_flowing=true`,
`flowing_streams=1`, player alive.

## 7. Unroute went pathless in the sandbox (fixed `e4b05c4`)

Sandbox log: `UnrouteDevice(...): 0 restored, 0 to fallback` — the unroute
identifies "our" streams by metadata `target.object` (discarded by the
sandbox daemon), matched nothing, then dropped the fallback link anyway →
stream pathless → player died on stream error. `unroute_device` now also
recognizes streams held by fallback links into this EQ and restores each
with real port links into its recorded original device — verify-before-drop,
link-first so the stream is never pathless; a failed restore keeps the link
and the heal retries. Pairing/pw-link plumbing shared via
`pair_stream_ports` + `port_id_refs`.

## 8. Diagnostics traps (cost half a day, documented so they are not repeated)

- **gdbus bool syntax**: `SetRoutingEnabled b:true` is a PARSE ERROR
  (`expected value: b:true ^`) — gdbus wants bare `true`/`false`. Every
  D-Bus probe using `b:` silently never reached the app; one suspected
  "remote toggle is a no-op" bug (Bug A) was invalidated by this. The
  harness's `dbus.py` wrapper is correct; only raw gdbus calls trip.
- **Backgrounded processes die with the tool call**: anything started with
  `&` (flatpak, pw-play) must be started under `setsid nohup ... & disown`
  or it is killed when the tool call times out. Three test rounds were
  invalidated by flatpak/tone deaths this caused.
- **Test tones expire**: 90 s/600 s tones finished mid-experiment and faked
  "stream killed" symptoms; the `ps -p $PID` check also hits the setsid
  wrapper, not the player child — check the stream node in pw-dump instead.
- **Wet/dry 0.0/0.0 RMS in T3b was environmental**: a leftover flatpak
  instance polluted the captures; with a clean environment the suite is
  47/47 (`wet=27119.2 dry=8439.8`, ~+10 dB measured).
- **Leftover instances hold the flock**: a second launch (native or
  flatpak) is refused while one runs; kill by PID before testing.
